01 — Problem Diagnosis

Why the old app was slow & broken

🔴
Route refresh → goes to first page This is a classic Vercel/SPA issue. There's no vercel.json rewrites config, so all routes 404 and redirect to /. Fix: add {"rewrites": [{"source": "/(.*)", "destination": "/"}]} OR switch to Next.js App Router which handles this natively.
🔴
Voice AI slowing down after 1–2 min Gemini Live API sessions accumulate context/audio buffer. The fix is session chunking: every 90 seconds, summarize and start a new Gemini session with the summary as context. Also: stream audio via WebSocket, don't batch it.
🟡
Vercel slowness Free Vercel has cold starts on serverless functions. Every API call wakes a new instance. Solution: use Next.js Edge Runtime for hot paths + move heavy AI logic to a persistent backend (Railway/Render).
🟡
Supabase free tier Free Supabase pauses after 1 week inactivity and has row limits. For SaaS use Supabase Pro ($25/mo) or keep free but add a keep-alive ping. The schema itself is fine — Supabase + PostgreSQL is the right move from Firebase.
🔵
Junk/temporary code Without seeing the actual codebase, common issues in AI-studio-generated apps: unused imports everywhere, no React.memo/useMemo, no code splitting, all routes loaded eagerly, and Gemini API called directly from the browser (exposes your key).

06 — Voice AI Fix

How to fix the slowdown after 1–2 minutes

ProblemRoot CauseFix
Slow after 1–2 minGemini context grows unboundedly — more tokens = more latencySession chunking every 90s
Audio delayBatching audio instead of streamingWebSocket streaming, 250ms chunks
Cold startsVercel serverless wakes per requestPersistent Railway WS server
Key exposedGemini called from browserServer-side proxy only
No reconnectNo session recovery logicRedis session state OR Supabase row
💡
Session Chunking Algorithm
1. Start Gemini Live session with system prompt + business context
2. Every 90 seconds OR when transcript hits ~4000 tokens: call Gemini to generate a 200-word summary
3. Start a NEW Gemini session with: system prompt + summary as context
4. User never notices — conversation continues seamlessly
This keeps each Gemini session small and fast forever.

10 — Final Recommendation

Rebuild from scratch — here's why

✅
Rebuild is the right call The old app has 4 fundamental architectural problems (routing, voice, cold starts, security) that can't be fixed by patching — they require structural changes. Since you're already on Supabase and Gemini, the rebuild reuses your data model and AI logic. With Next.js App Router + the module structure above, you get a clean, scalable codebase where new features are just new folders.
